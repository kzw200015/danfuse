# 不做 live 存储模式，绑定的弹幕一律落库

原设计里绑定有两种存储模式：snapshot 拉取后落库，live 播放时向平台现取并短期缓存。我们只保留落库这一种，去掉了存储模式这个概念和 `bindings.mode` 列。

理由：
- 落库的弹幕比现取的更全。B 站的 XML 弹幕只给最新的一个滚动窗口，每次拉取都把当时的窗口并进来，弹幕越积越多；现取只能看到当下这一个窗口。
- 新集弹幕的增长由追更的自动重新拉取覆盖。
- 弹幕源下架后，已落库的弹幕还在。
- 播放时只读库，没有现取时等待 B 站请求的延迟，也不会因为 B 站限流或故障而拿不到弹幕。
- "不想落库、临时看一下"的场景交给以后的上游 Provider：不用绑定，搜到就能看。

## Consequences

- 本地 Provider 只读库，不向平台现取。现取弹幕、以及这些弹幕的缓存，只归上游 Provider。上游 Provider 与本地 Provider 在聚合层下平级，不互为上下游。
- 弹幕的读取路径和身份仍然不能假定弹幕已落库，因为上游 Provider 的虚拟集不落库：cid 由平台与原始 ID 现算，校正与跨源去重是不访问数据库的纯计算。
