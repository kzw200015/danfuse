# 按季上传留下一个文件夹的季绑定

按季上传原本是一次性的，不留下记录，建出的绑定和在集面板上传的没有区别。这样一来，传错了一整季，只能逐集删除。我们改为每次按季上传都留下一个季绑定：季绑定从"一季 ↔ 一个合集"扩展为"一季 ↔ 一个合集，或一次按季上传的文件夹"，用 `kind` 区分两种，做法和 ADR 0004 给绑定加 `kind` 一样。建出的文件绑定用 `season_binding_id` 记着来源，删除季绑定时可以"一起删"。

文件夹的季绑定只记着那次上传建出的绑定。它不补建、不追更、不会失效，不保存集号规则、集号对应和条目表，只能删除。ADR 0001 说的补建、处理过的记录、条目表都只属于合集的季绑定。

## Considered Options

- **另立一个概念（如"上传批次"）**：不必让季绑定兼容没有合集的情况，但季面板要另有一套列表、卡片、"一起删"和绑定上的来源标签，与季绑定几乎一样。
- **不留记录，在季面板提供"删除本季全部文件绑定"**：最省事，但会连在集面板上单独上传的文件绑定一起删掉，删掉的不是"这一批"。
- **文件夹的季绑定也保存条目表**：能看出上传时有哪些条目没建出绑定。但这些条目的文件没有上传，无法据此补建，而且建出的绑定被单独删掉后，条目表就和实际对不上了；"建出 N 个绑定"和各绑定的标题（条目名称）已经说清楚这一批是什么。

## Consequences

- `season_bindings` 里只属于合集的列（适配器、合集引用、集号对应、集号规则等）对文件夹的季绑定为空，由 CHECK 约束守住；文件夹的季绑定的追更恒为关，追更的扫描自然不会碰到它。
- 文件绑定可以带 `season_binding_id`，但只能指向文件夹的季绑定；链接绑定只能指向合集的季绑定。
- 按季上传要在同一个事务里写季绑定和绑定，所以从 `binding` 领域移到 `seasonbinding`，由它开事务、把 `pgx.Tx` 交给 `binding.Service` 写绑定和文件（与补建相同）。
