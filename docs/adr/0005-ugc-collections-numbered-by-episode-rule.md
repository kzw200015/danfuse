# 投稿合集与多 P 投稿展开到分 P，合集序号由集号规则从条目名称认出

投稿合集和多 P 投稿是 UP 主自己排的，里面常混着不是正片的视频：PV、预告、"周更"占位的分 P，或者整部番的多 P 合辑与逐集投稿并存。按位置或分 P 号编号时，混进一个杂项，后面的集号就整体错开；UP 主往多 P 里插一个分 P，位置也跟着变；合集里的多 P 稿件若只取 P1，几乎没有用处。我们决定：

1. 投稿合集展开到分 P：每个稿件的每个分 P 都是一个条目，条目名称为"稿件标题 / 分 P 标题"（分 P 标题为空或与稿件标题相同时只有稿件标题）；多 P 投稿的条目名称同样如此。两种合集一律不按位置、不按分 P 号编号。
2. 合集序号由季绑定上的**集号规则**从条目名称认出，认不出的条目对不上。集号规则是一组 RE2 正则（1～10 条）：
   - 每一条都在名称里找，取集号（捕获组）结束得最靠后的那一处；一样靠后时取排在前面的正则。名称是"稿件标题 / 分 P 标题"，越靠后越具体，两级都写了集号时以分 P 的为准。有名为 `episode` 的捕获组时取它，否则取第一个捕获组。都匹配不上为对不上；取到的不是整数时对不上，不退而取别的匹配。
   - 先按名称原文匹配（用户照着看到的名称写），每一条都匹配不上再按清洗为 NFKC 的名称匹配（全角的数字、字母也能认出）。
   - 默认规则是写明集号的写法：`S01E11`、`第N话`/`第N集`、`EPN`，取自搜索、match 认名称的那张表（`catalog.ParseName` 的 `namePatterns`）；再加上名称结尾的 `/ N`（分 P 标题只写了集号）。`/ N` 认的是源适配器拼名称时的分隔，只属于集号规则，不放进那张表。不认没有标注的数字。`/ N` 也会认出"全12集…周更 / 05"这类合辑的分 P：合集里同时有逐集投稿时两边撞号、一起对不上，用户在这个季绑定的规则里删掉 `/ N` 那一条即可。分 P 标题只写集号的合集比这种混放的合集常见，默认认出前者，后者由用户调整。
   - 预览、创建时都明确传入规则，接口不替调用方选默认值；默认规则由单独的接口给出，管理界面拿它作为编辑的起点和"恢复默认"的内容。季绑定保存规则的副本：之后为了搜索调整那张表，不会改变已有季绑定认出的集号。用户可以删掉、调整顺序、新增正则，也可以恢复默认。
3. 番剧不用集号规则：集号与正片由平台给出，规则只对适配器标明"按规则编号"的合集生效。
4. 改集号规则和改集号对应一样，只影响还没处理过的条目：在改规则的事务里按保存的条目名称重新认集号，不请求平台；进行中的补建拉取每个条目之前重新读它的序号（正在拉取的那个条目按拉取前的序号写入，与改集号对应相同）。

## Considered Options

- **过滤掉合集里的多 P 稿件**：最小的改动。没有选：剔除之后要么空出序号（中间的杂项照样让后面错开），要么重新编号（每个条目的序号取决于别的稿件现在有几个分 P，分 P 一变整体挪位）；也会误伤把一集拆成上下两个分 P 的正片。
- **只加一个排除用的正则，仍按位置编号**：排除之后位置照样不稳定，插入、调序、漏传一集都会让后面错开。
- **展开到分 P 后按展开的位置编号**：任何一个稿件加一个分 P，它后面的位置都往后挪。
- **一条正则同时认出名称、季号、集号，搜索与集号规则共用**：名称是去掉季号、集号标注之后剩下的部分，标注常夹在中间，捕获组只能抓连续的一段；季号、集号的写法任意组合、顺序不定，合成一条写不下。改为一张按优先级排列的正则表（命名捕获组 `season`、`episode`），搜索按表认季号、集号，集号规则的默认值取表里带 `episode` 组的几条，再加上 `/ N`。
- **集号规则只有一条正则、留空为内置规则**：内置规则藏在代码里，看不出它认哪些写法，也不能只去掉其中一种；合成一条正则又要多个捕获组。改为一组正则，默认规则直接列出来。
- **默认规则兜底认名称末尾的数字**（整个合集都没有写明集号时启用）：没有选：是否启用取决于合集里别的条目，同一个条目的结果会因为合集里多了一条写明集号的条目而改变，看不明白。改为默认规则无条件地认结尾的 `/ N`：` / ` 是名称里两级标题的分隔，紧跟它、又在结尾的数字是整个分 P 标题，不是标题里随便一个数字。
- **默认规则不认 `/ N`，由用户按合集加上**：混放逐集投稿与合辑的合集开箱即用。没有选：分 P 标题只写集号的合集更常见，每个都要用户自己加规则。
- **按优先级取第一条匹配上的**：规则的顺序决定一切，但稿件标题和分 P 标题都写了集号时（"某番 第1集 / 第3集"），稿件标题里的先被认出。改为按位置取最靠后的，顺序只在位置一样时起作用。

## Consequences

- 条目的 ref 仍是 `{aid, page}`，与单集绑定同一套格式，手动绑过的同一个分 P 能被认出来。
- 季绑定记着合集是否按规则编号（每次列出时由适配器给出），改规则时据此决定要不要重新认集号。
- 列出投稿合集要取一个稿件的 view 才知道各稿件的分 P；合集里的稿件都取不到 view 时这次列出失败，不退回到只列 P1。
