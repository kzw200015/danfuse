# 剧以 TMDB ID 为身份，没有的退回自然键

剧原来只按自然键（类型、标题、年份）对应，刮削后换元数据语言、换提供者、重新识别都会改标题或年份，同步就多出一部剧，旧的那部连同绑定留在目录里。我们改为：有 TMDB ID 的剧以（类型，TMDB ID）为身份，标题和年份只是随目录源覆盖的属性；没有 TMDB ID 的剧仍以（类型，标题，年份）为身份。同步先按 TMDB ID 找，找不到再按自然键在没有 TMDB ID 的剧里找（已有目录里的剧借此补上 TMDB ID），都找不到才新建。

理由：
- 只认 TMDB，不认任意外部 ID（TVDB、IMDb、AniDB、AniList）。TMDB 是 Jellyfin 对剧集和电影的默认提供者，一列就够；认任意外部 ID 时一部剧可能按不同提供者对上两部本地剧，要定合并规则。只用 AniDB 刮削的剧退回自然键，等于现状。
- TMDB 的电视剧和电影是两套编号，所以身份是（类型，TMDB ID），不是单独的 TMDB ID。
- 自然键的唯一约束只对没有 TMDB ID 的剧生效。有 TMDB ID 的剧标题可以随意变，不能再被标题年份约束住；两部 TMDB 不同、标题年份相同的剧也因此可以共存。
- 自然键匹配只在没有 TMDB ID 的剧里找，不"换身份"。在 Jellyfin 里重新识别成另一个 TMDB 条目是用户主动改了"这是哪部剧"，按新剧处理，旧的由用户删除；若顺带覆盖旧的 TMDB ID，标题年份一变又对不上，等于回到原点。

## Consequences

- 同一个 TMDB 条目分在两个媒体库、标题还不一样时合成一部剧，标题由后处理的那个决定；原来是两部。
- 只改剧的身份，季仍按季号、集仍按集号对应。
- TMDB ID 值不是正整数时当作没有 TMDB ID，仍算刮削过，同步记一条警告。
