# 季绑定保存表单，补建按槽位把绑定对齐到表单

> 替代 ADR 0001、0008、0009，以及 ADR 0004、0005 中各自注明的条目。
> Consequences 第 2 条说的唯一约束已由 ADR 0011 去掉；ref 仍是合集的规范写法，保存表单时靠它判断换没换合集。

季绑定仍由补建落成普通的绑定，读取弹幕的路径和单集绑定一样，这一点沿用 ADR 0001。

原来，合集的季绑定按弹幕源记住"处理过"的条目，文件夹的季绑定只记着那次上传建出的绑定。表单改过之后，处理过的记录、条目表和实际的绑定就对不上了；传错的文件夹也只能删掉重来。

我们决定：

1. **两种季绑定都保存表单，绑定一律由表单派生**，表单创建之后都能改。文件夹的条目连同弹幕文件存在季绑定名下。建出的文件绑定不持有文件，从条目的文件解析。
2. **以集为槽位**：每个季绑定在每一集上至多有一个建出的绑定。补建只看当前的条目，不记住处理过的条目，也不记住见过的条目。
3. **只有保存表单会删除**：补建只新建，或者把弹幕源变了的绑定替换掉。没有条目的槽位，补建从不删除里面的绑定。用户保存表单、在预览里确认之后，这些绑定才会删除。
4. **建出的绑定归季绑定管**：不能单独删除，不能追加文件，也不能脱离季绑定。删除季绑定时，它建出的绑定一起删除。

## Considered Options

- **保留"处理过"的记录**：表单可以改之后，这份记录就说不清了。改了集号对应，处理过的条目要不要挪到新的集？换了合集，旧合集的记录要不要留？
- **记住见过的条目**：稿件 A（第 5 集）下架，重新投稿为 B（也是第 5 集）。A 和 B 会一起算作集号重复：A 的绑定被删，B 也建不出来。
- **补建也删除没有条目的槽位**：平台上下架、改名、列不全时，绑定会连同调好的偏移一起被删掉，用户事先不知道。
- **建出的绑定可以单独删除**：删掉之后，下一次补建要么把它补回来，要么还要再记一份"别补"。要排除某一集，改集号对应就行。
- **合集的条目、文件夹的条目和 `binding_files` 共用表**：前者是每次列出都会重写的缓存，后者是表单本身；"恰好有一个属主"也没法用约束表达。

## Consequences

- 保存表单与补建互斥。保存时以重新列出的合集为准。
- 贴的链接单独保存，不进 ref，理由同 ADR 0009 第 1 条。查重和唯一约束都依赖 ref 是合集的规范写法。
- 已部署的数据只转换、不修正。用户删掉过的、建出的绑定，下一次补建时会补回来。
