# 不做上游聚合，弹弹 API 只回答本地目录

原设计里，弹弹 API 背后有一层聚合：本地目录和各个上游平台（B 站番剧、影视的实时搜索，不入库，用虚拟 ID 表示）都是 Provider，按可信度和优先级合并结果。我们放弃了上游聚合，弹弹 API 只回答本地目录：搜索、识别只查目录，弹幕只读绑定落库的弹幕；Provider 接口、聚合层和 ID 号段一并去掉。

理由：
- 复杂度过高：识别是否准确、多个来源的排序与去重、虚拟条目的编码与缓存，每一项都比本地这条路复杂得多；只有一个实现时还要为它维护一层抽象。
- 与其他项目的功能重合：从上游平台实时搜索、聚合弹幕已经有其他项目在做，danfuse 只做自托管目录上的绑定。
