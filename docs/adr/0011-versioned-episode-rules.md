# 集号规则版本化，保留标题层级并显式调整集号

> 扩展 ADR 0005 的集号规则；保留 ADR 0010 的表单、派生、槽位、租约和写入语义。

## Context

投稿合集、多 P 投稿和文件夹的标题常同时包含总话数、更新进度、来源季与分集号。把两级标题拼起来交给同一组正则，会让稿件中的"更至第2话"盖过无法识别的分 P 标题；原文优先的匹配还会在下级写全角数字时取到上级数字。

同一合集的两季通常分别从 1 编号，本地却可能合并为一个 25 集的季。单一整组映射无法把第一季 01 和第二季 01 同时对应到 1、13。为每种情况新增手写正则也无法完成加法；改变已有规则算法则会静默重解释绑定。

## Decision

1. 保存版本化 `EpisodeRuleConfig`，包含整组范围、按序的正则及每条集号加减值、带种类的排除正则。保存实际规则快照，不只保存模板 ID。
2. version 1 继续完整标题、原文优先、全部失败后才 NFKC 的旧行为，只允许加减零和无排除。旧正则数组迁移为这种配置。已有绑定只有在编辑草稿中主动使用新版模板、预览并保存后才升级。
3. version 2 使用真实 `labelParts`：单层稿件或两层稿件/分 P、文件夹/条目。`label` 保持展示和旧匹配用途，不从显示字符串拆 `/` 推断层级。默认匹配下级标题，独立下级不匹配时不回退上级；缺少历史层级时明确报错。
4. 新版按 ref 去重，先在下级标题做排除，再选正向范围、NFKC、取捕获组、应用命中规则加减值、检查重复，最后应用已有整组映射与槽位。仍取捕获组结束位置最靠后的匹配，同位置前面的规则优先；来源季捕获只用于诊断。
5. 新建默认覆盖第几话/集、季号加数字、季号加第几话、S/E、EP、纯数字和数字加空格标题。仅正片默认开启，以 `nonRegular` 排除快照表达；关闭只删除此类，保留自定义排除。排除只看下级，避免总标题的"＋特别篇"误排正片。
6. 加减值由用户明确配置，在重复判定之前生效。例如我心里危险的东西第一季加 0、第二季加 12，第二季09 得到 21。来源季不等于本地季，不按总集数、分 P 顺序或最大现存集号猜测。
7. 后端纯函数生成模板；前端以模板为主，保留高级 RE2。指定季模板覆盖数字和规范中文季号；未标季模板按标题开头限定，不自动视作第一季。单组正向 1～10 条、排除最多 10 条，各不超过 200 字符。
8. API 兼容旧 `episodePatterns` 请求并提供正则投影，但不能同时提交两个字段。已存 version 2 的绑定拒绝旧字段/version 1 的写回（409），在事务加锁后再检查，防止旧客户端或并发请求丢失配置。
9. 原状态枚举、number 清空等语义保持，诊断另附原因码、匹配/归一化/加减证据、排除项和冲突行。它读取时计算、不落库、不含 ref。配置变化让旧预览过期，仍需完成新预览和既有删除/替换确认。

## Considered Options

- **只添加正则**：无法进行跨季加减，无法在统一完整标题输入中可靠区别更新进度和分 P 集号，也无法解释排除与重复原因。
- **自动按顺序编号或累计前季长度**：插入 OAD、删除分 P、缺集或目录后续同步都会改变结果，且来源季与本地季关系并不固定。
- **允许同一季重复绑定一个合集，分别取来源季**：绕开了现有唯一约束，会让同源和槽位关系更难解释；采用一个季绑定中多条显式规则。
- **解析展示字符串的最后一个 `/`**：标题本身可以包含 `/`；结构化字段在适配器和文件夹已有层级处生成才可靠。
- **把新版默认算法直接应用到旧绑定**：可能改掉现有对应关系、引起删除或替换；旧版继续可读，新版主动升级。
- **前后端各自生成模板**：两套正则容易漂移；后端提供无平台/数据库 IO 的模板端点，前端只编辑返回快照。

## Consequences

- 迁移新增 `episode_rule JSONB` 替代旧数组，新增可空 `label_parts text[]`。历史标题不猜层级，不修改绑定、弹幕、时间偏移、追更、映射或平台集号。sqlc 和结构文档由生成工具更新。
- 缓存只保存平台集号；规则集号读取时算，详情和补建不会重复加减。补建可更新层级，却不会自动升级规则。
- 原始集号、调整结果与本地集号使用宽整数运算并限制在 PostgreSQL integer 范围；越界时条目对不上，诊断显示原因。
- 保存沿用事务、季绑定租约与槽位。相同来源仍对到同一集则保留 ID、弹幕和时间偏移；缺失槽位只在保存时删除，补建不删除。
- 存在 version 2 配置时拒绝数据库有损回退；仅全部为 version 1 才允许还原旧数组结构。
- 平台直接提供的番剧集号、搜索、文件名识别和弹弹 API 的名称解析不改变。新增日志只扩充现有补建记录的规则版本、识别、排除和重复计数。
